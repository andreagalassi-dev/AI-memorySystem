# Fase 1.3 — Cervello Unificatore (LangGraph Orchestrator) — Design

> Roadmap: `docs/PIANO-IMPLEMENTAZIONE.md` §Fase 1.3, `docs/piano_implementazione/01_fase1_pipeline.md`.
> **Evolve** il grafo P3.5 gia' esistente e maturo (`src/graph/pipeline.py`), non lo riscrive.

## Obiettivo

Il direttore d'orchestra: riceve la query dell'utente, la instrada al tool giusto e
fonde i risultati in una risposta affidabile. Usa i due binari costruiti:
Text-to-SQL sulle righe di 1.2 (`estrazione.righe_listino`) e il retrieval visivo di
1.1 (PixelRAG), oltre al RAG testuale gia' esistente. L'LLM (Gemma 4 / Nemotron via
MLX) sta dietro un Port.

## Principio: additivo e fail-closed

L'evoluzione e' **additiva e retrocompatibile**: i nuovi campi di `GraphState` e i
nuovi `Deps` (`llm`, `sql_query`, `visual_search`) sono opzionali; con `None` il
grafo si comporta esattamente come oggi (ramo NARRATIVE), **zero regressioni** sui
test P3/P4. Tutti i rami convergono su **guardrail (P3.1) -> finalize (P3.2)**
invariati: il guardrail codici e il "non lo so" valgono anche sulle risposte SQL
renderizzate dall'LLM (Defense in Depth).

## Punto 1 — LangGraph: State, Nodi, Routing

**State** (additivo a `GraphState`): `intent` (`STRUCTURED|VISUAL|NARRATIVE`),
`sql_params`, `sql_rows`, `visual_pages`. Il resto invariato.

**Routing deterministico** — `router_node` deriva `intent` da `classify_query`
(gia' da' `code/visual/natural/mixed` + `code_token`) + una whitelist di keyword
prezzo/quantita':
- `code` / prezzo / quantita' esatti -> **STRUCTURED** (tool SQL).
- `visual` -> **VISUAL** (tool PixelRAG).
- `natural` / `mixed` -> **NARRATIVE** (RAG testuale esistente).

**Nodi**:
```
router ─▶ STRUCTURED ─▶ sql_node ─▶ render(LLM) ─┐
       ─▶ VISUAL     ─▶ visual_node ──────────────┤─▶ guardrail ─▶ finalize
       ─▶ NARRATIVE  ─▶ retrieval→confidence→fusion→synthesis ─┘
```
`sql_node` e `visual_node` sono nuovi; `guardrail`/`finalize` restano. Fail-closed di
rete come i nodi esistenti (eccezione -> `system_error` -> BASSA).

## Punto 2 — Text-to-SQL sicuro (Text-to-Parameters)

**L'LLM non genera mai SQL eseguibile** (anti-injection + anti-allucinazione).
- Il `code_token` (dal router) -> `codes.canonical` -> `codice_normalizzato`. Il
  **campo richiesto** (prezzo/descrizione/quantita') da whitelist di keyword. Spesso
  zero LLM per estrarre i parametri.
- Query **template parametrizzata** con `psycopg.sql`: colonna via
  `sql.Identifier` da **whitelist chiusa**, valore via placeholder `%s`. Mai
  f-string/concatenazione. Esempio:
  `SELECT {col} FROM estrazione.righe_listino WHERE codice_normalizzato = %s`.
- **Difesa in profondita'**: connessione con ruolo DB **read-only**; si interroga
  solo `righe_listino` (Semantic Layer), mai tabelle grezze.
- **Fail-closed**: codice non in tabella -> "non lo so", mai un prezzo inventato.

## Punto 3 — Ports & Adapters (testare senza accendere il modello)

Estende il pattern `Deps` gia' esistente:
- **`LanguageModel`** (Port): `generate(system, user) -> str`. Adapter reale
  `MLXModel` (Gemma 4 / Nemotron via `mlx-lm`) **differito**; `FakeLLM`
  (pre-programmato) per i test. Serve sintesi narrativa e rendering righe SQL.
- **`sql_query`** in `Deps`: `Callable[[params], rows]` — reale psycopg su
  `righe_listino`, `FakeSqlExecutor` in memoria nei test.
- **`visual_search`** in `Deps`: PixelRAG (1.1), reale vs `FakeVisualIndex`.
- I test iniettano `Deps` con `FakeLLM` + sql/visual fake -> l'intero grafo 1.3 gira
  **senza MLX/Qdrant/Postgres**, come oggi i test iniettano `retrieve/synthesize`.

## Componenti (estende `src/graph/`)

```
llm.py              # Port LanguageModel + FakeLLM (+ MLXModel reale, differito)
tools/sql_tool.py   # Text-to-Parameters + query template parametrizzata + executor Port
tools/visual_tool.py# wrappa pixelrag (1.1) in risultato-pagina per il grafo
pipeline.py         # +intent nel router, +sql_node/visual_node/render, +branch
```

## Ordine di implementazione (un passo/commit, review prima di ognuno)

1. `llm.py` — Port `LanguageModel` + `FakeLLM` + test.
2. `sql_tool.py` — Text-to-Parameters + template parametrizzato + `FakeSqlExecutor`;
   test anti-injection + `needs_pg` su query reale.
3. Router `intent` (estensione deterministica di `classify_query`) + test.
4. `sql_node` + render + branch STRUCTURED nel grafo + test (FakeLLM).
5. `visual_tool` + `visual_node` + branch VISUAL + test (FakeVisualIndex).
6. e2e `answer()` sui tre intent + guardrail sulle risposte SQL.

## Fuori scopo

Serving reale MLX (Gemma 4 / Nemotron), merge Fase 2, integrazione ERP. 1.3 termina
con un grafo che instrada, interroga in sicurezza e sintetizza, dietro Port.
