# Fase 1.2 — Binario Estrazione Massiva Dati (DeepSeek-OCR-2 → PostgreSQL) — Design

> Roadmap: `docs/PIANO-IMPLEMENTAZIONE.md` §Fase 1.2, `docs/piano_implementazione/01_fase1_pipeline.md`.
> Regole: `docs/piano_implementazione/00_regole_procedure.md`.

## Obiettivo

Binario **parallelo e disaccoppiato** dagli altri: dato un PDF, individua le pagine
listino/tabella/griglia, ne estrae le righe strutturate e le carica in PostgreSQL
(SSOT). Scopo = *data entry*, non risposta alla chat. La chat leggerà queste righe
via Text-to-SQL (Fase 1.3): non è compito di 1.2.

## Principio: il modello è un "passacarte ignorante"

DeepSeek-OCR-2 legge i pixel e propone righe grezze. **Non gli deleghiamo nulla di
critico**: il `codice_normalizzato` (chiave del merge Fase 2) lo calcoliamo **noi**
in modo deterministico con `src/ingestion/codes.py::canonical`. Il modello non è
fonte di verità: è un OCR strutturante, validato a valle.

## Fail-Closed a due strati (il vincolo centrale)

Pydantic da solo NON basta: valida forma e tipo, ma un prezzo inventato plausibile
(`12.50` su una cella vuota) è un `Decimal` valido. Quindi:

1. **Strato FORMA — Pydantic.** Ogni riga grezza → `RigaGrezza` con
   `extra="forbid"` (campi inventati dal modello → errore), campi obbligatori,
   `prezzo >= 0`, `codice_originale` non vuoto. Riga malformata → **scarto
   `SHAPE_INVALID`**.
2. **Strato GROUNDING — deterministico, non-LLM, DB-free.** Il
   `codice_normalizzato` (calcolato da noi) deve corrispondere allo skeleton
   canonico di un token code-shaped **presente letteralmente** nel testo grezzo
   di *quella* pagina. Codice non ancorato → **scarto `CODICE_NON_ANCORATO`**
   (fabbricato). Estendibile a prezzo/quantità con lo stesso principio.

Righe che non superano **entrambi** gli strati → tabella `estrazione.scarti_estrazione`,
**mai** in silenzio nelle tabelle-dati. Regola d'oro: giusto oppure scartato, mai
sbagliato in silenzio.

> **Nota di design (grounding disaccoppiato dal DB) — Documentazione = Codice.**
> La bozza iniziale prevedeva il riuso di `guardrail.extract_candidates`. In
> implementazione si è scoperto che quella funzione dipende dai profili-brand su
> Postgres (`brands.all_extract_patterns`) e solleva a ogni chiamata senza DB. Il
> grounding è hot-path e dev'essere **puro, DB-free e testabile offline**: non ha
> senso interrogare un database per verificare se una stringa è letteralmente in
> una pagina di testo. Quindi `grounding.py` tokenizza in proprio i run
> code-shaped (stessa forma di `guardrail._TOKEN`) e riusa **solo** la
> normalizzazione GT-testata `codes.canonical`. Non serve *classificare* i codici
> della pagina (il filtro misure/date del guardrail), ma solo verificare la
> *presenza* di un codice già noto — questo alza anche il **recall** del grounding,
> perché non scarta i codici brand corti. Nessuna dipendenza da `guardrail`.

## Componenti (ports & adapters, testabili in isolamento)

```
src/ingestion/extraction/
  schema.py        # RigaGrezza (model-facing) + RigaListino (persistita) + MotivoScarto + Scarto
  extractor.py     # PORT TableExtractor (Protocol) + FakeExtractor (test, no modello)
  table_detect.py  # euristica deterministica: quali pagine sono tabelle (riusa page_features)
  enforce.py       # schema-enforcement via Instructor + retry (DIP: instructor da aggiungere)
  grounding.py     # strato 2: verbatim grounding DB-free (tokenizza + codes.canonical)
  load.py          # upsert righe valide + insert scarti (psycopg3, come src/registry)
  pipeline.py      # orchestratore: detect -> extract -> enforce -> ground -> load
```

Il modello reale DeepSeek-OCR-2 sta **dietro il port** `TableExtractor`. Sviluppiamo
enforce/grounding/load contro un `FakeExtractor` deterministico; l'adapter DeepSeek
è un modulo separato da innestare quando il modello sarà servito (endpoint
OpenAI-compat). Coerente con l'iniezione `extract_fn` già usata in `ingest_one.py`.

## Contratti Pydantic

```python
class RigaGrezza(BaseModel):
    """Cio' che il modello DEVE produrre (response_model di Instructor)."""
    model_config = ConfigDict(extra="forbid")
    codice_originale: str = Field(min_length=1)
    descrizione: str | None = None
    prezzo: Decimal | None = Field(default=None, ge=0)

class RigaListino(BaseModel):
    """Riga persistita: grezza + metadati calcolati da NOI."""
    codice_originale: str
    descrizione: str | None
    prezzo: Decimal | None
    codice_normalizzato: str   # = codes.canonical(codice_originale), non dal modello
    doc_stem: str
    page: int
```

`extra="forbid"` è la guardia anti-invenzione-di-struttura; il grounding è la
guardia anti-invenzione-di-valore. `strict` per-campo si potrà stringere sul corpus
reale (nota: l'output LLM è JSON, uno strict globale over-rigetta).

## Persistenza — schema Postgres `estrazione` (dedicato, isolato da `core`)

```sql
CREATE SCHEMA IF NOT EXISTS estrazione;

CREATE TABLE estrazione.righe_listino (
    doc_stem            text    NOT NULL,
    page                int     NOT NULL,
    codice_normalizzato text    NOT NULL,
    codice_originale    text    NOT NULL,
    descrizione         text,
    prezzo              numeric,
    updated_at          timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (doc_stem, page, codice_normalizzato)   -- upsert idempotente
);

CREATE TABLE estrazione.scarti_estrazione (
    id                          bigserial PRIMARY KEY,
    doc_stem                    text NOT NULL,
    page                        int  NOT NULL,
    codice_originale            text,
    codice_normalizzato_tentato text,
    payload_raw                 jsonb,          -- cosa ha emesso il modello
    motivo                      text NOT NULL,  -- MotivoScarto
    created_at                  timestamptz NOT NULL DEFAULT now()
);
```

`codice_normalizzato` = chiave esterna universale per il merge Fase 2 (SQL JOIN col
catalogo). Schema idempotente + eventuale seed, come `src/registry`.

## Flusso

`table_detect(pdf)` → pagine tabellari → per pagina `extractor.extract(ref)` (Fake o
DeepSeek) → `enforce` coerce/retry in `RigaGrezza` → per ogni riga valida calcoliamo
`codice_normalizzato` e `grounding` verifica il verbatim → `load` fa upsert delle
valide-ancorate in `righe_listino` e insert delle altre in `scarti_estrazione`.

## table_detect (euristica deterministica, tunabile sul corpus)

Riusa `page_classifier.page_features`: pagina candidata-tabella se testo ricco
(`chars >= T`) **e** segnale-griglia (molti `n_drawings` = bordi cella) **e** alta
densità di token code-shaped/numerici. Auditabile (feature + ragione), unit-testabile,
soglie da calibrare (territorio gate P1). Non modifica P2.5 né la Fase 1.0: la
ridondanza col fast-path sui born-digital è un compromesso accettato per il
disaccoppiamento dei binari.

## Testabilità & verifica

- `FakeExtractor` deterministico: unit test di enforce/grounding/load senza modello
  né rete.
- Test DB con il pattern `needs_pg` di `tests/conftest.py` (Postgres del compose).
- `FakeExtractor` che emette righe con codici fabbricati → verifica che il grounding
  li scarti (test del Fail-Closed).
