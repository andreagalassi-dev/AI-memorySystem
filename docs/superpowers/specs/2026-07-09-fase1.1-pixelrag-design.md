# Fase 1.1 — PixelRAG (Retrieval Visivo) — Design

> Roadmap: `docs/PIANO-IMPLEMENTAZIONE.md` §Fase 1.1, `docs/piano_implementazione/01_fase1_pipeline.md`.
> Costruisce sopra P2.7 (retrieval visivo ColQwen2 gia' esistente, `src/retrieval/visual.py`).

## Obiettivo

Binario **gemello "cerca"** del binario "estrai" (1.2): tutte le pagine con grafica
vengono ingerite visivamente, ogni pagina renderizzata in **tile screenshot ad alta
risoluzione**, i vettori visivi caricati su Qdrant. Il chatbot risponde alle domande
visive (esplosi, schemi) da questo indice; **BM25 sparse resta in parallelo** per i
codici alfanumerici esatti. Evolve il binario P2.7 dietro Port; il modello passa da
ColQwen2 a Qwen3-VL-Embedding quando servito, senza toccare il resto.

## Tre decisioni cardine (approvate)

1. **Embedder dietro Port** — adapter concreto **ColQwen2** ora (gia' validato in
   P2.7); **Qwen3-VL-Embedding** poi, drop-in.
2. **Tile hi-res + thumbnail di pagina** — i tile preservano il dettaglio degli
   esplosi; il thumbnail dà il contesto globale.
3. **Ibridazione via router + RRF cross-segnale su `(doc, page)`** — RRF perche' i
   punteggi assoluti BM25 vs Qwen sono **incomparabili**: si fondono i *rank*.

## Punto 1 — Tiling & Risoluzione

L'attenzione dei VLM-embedder e' **quadratica** nei patch: scalare l'intera pagina
sotto il tetto (P2.7: cap 1540px) distrugge i micro-dettagli di un esploso A3.
Strategia:

- Render pagina a **DPI 200–300**; split in **griglia di tile** (lato `tile_px`,
  es. 1024) con **overlap ~12%**: una leader-line/codice a cavallo del confine resta
  intero in almeno un tile.
- Ogni tile → un punto vettoriale con payload `(doc, page, row, col, bbox)`.
- **+1 thumbnail/pagina** (a bassa risoluzione) come punto per il contesto globale.
- A retrieval i tile si **ricompongono per `(doc, page)`** (score pagina = max dei
  suoi tile).
- **Densita' adattiva** guidata dal flag "grafica" di P2.5 (riuso, non ri-classifico).

**Geometria pura e testabile senza PDF:** `tile_grid(page_w_px, page_h_px, tile_px,
overlap) -> list[Tile]` calcola `(row, col, x0, y0, w, h)` con sliding-window +
**clamp del tile finale al bordo** (copertura totale, tile di dimensione uniforme).
Il rendering (`fitz.get_pixmap` + crop) e' un wrapper I/O separato.

## Punto 2 — Ports & Adapters

- **`VisualEmbedder`** (Protocol): `embed_tiles(images) -> vectors`,
  `embed_query(text) -> vector`. Adapter: `ColQwen2Embedder` (wrappa `visual.py`),
  poi `Qwen3VLEmbedder`.
- **`VisualIndex`** (Protocol): `upsert(points)`, `search(query_vec, k, filter) ->
  hits`. Adapter: `QdrantVisualIndex` (collection `aike_pages_visual`, MaxSim) +
  **`FakeVisualIndex`** (hit pre-programmati) per i test.
- Retrieval/tiling/fusione testabili **senza GPU ne' Qdrant** col Fake; i test su
  modello/Qdrant reali dietro marker (skip se assenti), dichiarati onestamente.

## Punto 3 — Ibridazione

Il vettoriale visivo e' pessimo sui codici esatti (`AB-12345-X`): BM25 sparse resta
indispensabile. Router deterministico esteso (riuso `retrieval/router.classify_query`):

- `code` → **BM25 sparse only** (mai visivo).
- visivo puro → **PixelRAG only** (rispetta "DB visivo esclusivo" del Piano).
- `mixed` → **RRF su `(doc, page)`**: i chunk testuali e i tile visivi portano
  entrambi `(doc, page)`; la fusione promuove le pagine presenti in **entrambi** i
  segnali (chiave universale `doc+page`, come `codice_normalizzato` per il merge 1.2).
- **RBAC/versioning** riusano `access_filter`/`version_filter` di `search.py` anche
  sui punti visivi.

## Componenti (`src/retrieval/pixelrag/`)

```
tiling.py    # geometria PURA (tile_grid) + render I/O (fitz get_pixmap + crop)
embedder.py  # Port VisualEmbedder + ColQwen2Embedder (wrappa visual.py)
index.py     # Port VisualIndex + QdrantVisualIndex + FakeVisualIndex
search.py    # visual_search: embed_query -> index.search -> ricompone tile->pagina
hybrid.py    # router esteso: fonde testo(search.py)+visivo su (doc,page) via RRF
ingest.py    # orchestratore: pagina grafica -> tiling -> embed -> upsert (payload+RBAC)
```

## Ordine di implementazione (un passo/commit, review prima di ognuno)

1. `tiling.py` (geometria pura) + test rigorosi della matematica dei tile (no PDF).
2. `index.py` Port + `FakeVisualIndex` + test.
3. `embedder.py` Port + adapter ColQwen2 (wrappa P2.7).
4. `search.py` visual (ricomposizione tile→pagina) + test col Fake.
5. `hybrid.py` (fusione RRF cross-segnale) + test.
6. `ingest.py` orchestratore + e2e col Fake; poi integrazione Qdrant reale.

## Fuori scopo

Serving reale Qwen3-VL-Embedding, Cervello Unificatore (1.3), Text-to-SQL, merge
(Fase 2). 1.1 termina consegnando un retrieval visivo ibrido, filtrato per RBAC.
